# 可重建的水下滑翔机水面尾迹场

## 目标

让水下滑翔机在接近水面航行时，产生可辨认、连续、方向正确且随时间/深度衰减的表面扰动。现有 Built-in Render Pipeline 海面和艇体近场压力效果保留；新增的尾迹必须沿滑翔机实际走过的轨迹留下，而不是每帧整体跟着当前位置重新计算。

这是视觉近似，不是 CFD 或动力学模型。不得把水面效果反馈到轨迹、海流、预测、遥测、导出或控制。

## 用户确认的范围

- 使用 Unity 原生实现，不迁移 HDRP，不引入第三方水面包或 CFD 求解器。
- 只改变水面/尾迹渲染；不改 UI、现有功能键、输入参数、仿真数据和动力学语义。
- 尾迹按播放时间可重建：暂停保持不动；同一播放状态重复 seek/replay 得到相同尾迹；倒放按反向行进方向生成尾迹。
- 近水面尾迹清楚但克制。滑翔机在水下，不应默认生成船体破水式的大面积白沫或发光斑块。

## 现状与问题

`WaterSurfaceView` 在 Built-in RP 下创建局部水网格及材质，并把播放时间、交互目标的位置/速度和深度送入 `DeterministicOceanSurface.shader`。shader 的 `EvaluateInteractionSurface` 每次只依据当前交互位置和速度解析船体压力及 Kelvin 式波形，因此没有航迹历史。近景关闭交互的截图仍保留相似的大面积蓝白镜面高光，掩盖了较弱的尾迹。

可复核证据：`artifacts/water-kelvin-close-top-no-wake.png`、`artifacts/water-kelvin-reverse-local.png`。当前 Build 记录在 `TestResults/WindowsBuild.log`；旧图只作为问题基线，不作为新方案验收。

## 方案

新增一个水面视觉层拥有的、局部且有界的尾迹场。尾迹场由当前播放状态对应的近期轨迹样本确定性重建，并以水面局部纹理表达高度扰动及用于着色的尾迹强度；水面 shader 将场采样为顶点位移/法线变化，并以低强度呈现表面粗糙度或细微泡沫信号。保留现有背景海浪与近船体压力核，但避免将旧的瞬时解析长尾与历史尾迹重复叠加。

轨迹采样必须复用滑翔机显示正在使用的拟合轨迹/坐标映射，不能另起一套平滑曲线造成尾迹与艇体错位。若当前组件边界不允许读取指定播放时间的位置和深度，只增加最小的只读视觉数据接口；不得改变其业务输出。

尾迹场使用固定的水面局部世界坐标映射和受限纹理尺寸。播放推进时允许增量更新；初始化、seek、方向切换、轨迹重建或尾迹场覆盖范围变化时，从播放时间和轨迹确定性重建。缓存仅是性能优化，不能成为正确性的来源。实现需避免每顶点遍历大量历史点，也不能每帧对整张高分辨率贴图做 CPU 像素循环；具体的纹理绘制/重建实现由后续实施计划选择，并针对 Built-in RP 及目标 Windows Player 验证。

## 时间与方向语义

- 正向播放：当前尾迹只包含播放时间之前、滑翔机已经走过的有限历史段；历史点越旧，扰动越弱。
- 倒放：若当前轨迹时间为 `t`，尾迹从已倒放经过的 `t` 到 `t + age` 路径重建，位于当前反向行进方向的后方；不能简单翻转相机坐标或用正向历史残留。
- 暂停：播放游标不变，尾迹纹理和表面外观不变；背景海浪继续遵守现有的播放时间驱动规则。
- Seek/重播：清除不属于目标状态的缓存并从轨迹重建；相同轨迹、时间、方向与深度必须输出一致结果。
- 深度：每个历史路径段按该段对应的滑翔机深度连续衰减；当前及历史深度变化不得出现硬阈值闪切。
- 零水平速度、无交互目标、无效轨迹：不生成新的路径扰动；不存在的历史场清零或保持为无效状态。
- 轨迹重建/切换：清理旧轨迹的缓存，不能把上一任务尾迹带入新任务。

## 可见表现

- 船体周围有小尺度压力/表面坡度响应，并平滑接入沿航迹延伸的尾迹。
- 尾迹主方向、两侧扩散波和衰减可读，不呈现两颗分离的亮斑、规则同心圆、尖锐孤峰、长条过曝或固定在世界坐标中的痕迹。
- 倒放后尾迹相对艇体的方向反转；暂停和重复 seek 无漂移或残留不一致。
- 关闭交互时背景水面不出现尾迹贴图效果；背景高光应降低到不再冒充尾迹，但不将整片海面压成无反射的平板。
- 深潜时表面扰动平顺减弱。除非艇体实际接近破水状态并通过视觉验证，否则不加明显白色泡沫。

## 组件边界

- `WaterSurfaceView` 继续拥有水面材质、播放时间和交互绑定；管理或持有尾迹场资源生命周期。
- 播放轨迹采样通过现有显示轨迹数据提供只读位置/深度采样；禁止改写 `PlaybackModel` 的时间、速度、方向或轨迹。
- `DeterministicOceanSurface.shader` 继续负责背景波浪、近场水面形变与最终着色，并新增受限的尾迹场采样。
- 纹理分辨率、更新频率和绘制样本预算作为内部质量策略，不新增面向用户的 UI 控件或输入参数。
- 所有 RenderTexture/临时网格/材质等资源须成对创建释放；格式或硬件不支持时应降级到现有解析水面，而不是让水面消失或引发错误。

## 验收

1. 在原有标准近水面播放状态用 Windows Player 截图，水面波纹与滑翔机位置相连，沿轨迹连续展开，能明显区分于关闭尾迹时的背景反光。
2. 正放与倒放图中，尾迹均落在相对当前行进方向的后方。
3. 暂停期间重复截图像素稳定；seek 到同一时间后重建结果与第一次一致。
4. 由浅至深连续取样，尾迹强度连续减弱，无突然消失/闪烁。
5. 清除/更换轨迹后旧尾迹不残留；零速和无目标时无新尾迹。
6. Windows Player 构建成功；Player 日志无 shader、纹理资源和运行时异常。检查基线与启用尾迹的性能差异，并控制纹理/更新预算。
7. UI、参数输入、轨迹、海流、预测、遥测、导出和动力学行为不变。自动化 Unity 测试只有用户明确要求时才执行；实现阶段仍应新增/更新相应测试并执行允许的构建及运行截图验证。

## 非目标与风险

- 不承诺定量复现真实流场、表面张力、粘性、风浪耦合、白浪破碎或滑翔机水动力。
- 局部纹理分辨率有限，可能带来采样模糊/格纹；通过世界尺寸映射、滤波和有界更新解决，不能靠增加高光来遮掩。
- 轨迹时间采样和水面局部坐标的任何不一致会使尾迹偏离艇体；实施时必须用已知直线轨迹校验位置、方向和历史顺序。
- 若目标设备性能不足，先降低场分辨率/更新频率并报告视觉取舍，不得悄悄改变仿真时间或删改现有功能。
